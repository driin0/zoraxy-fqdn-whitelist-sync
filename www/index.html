How the sync works
Each FQDN's A/AAAA records are resolved every interval and added to the whitelist, tagged fqdn-sync:<fqdn>.
Fail-closed for FQDNs: if a name stops resolving, its IPs are removed once the grace window expires.
An FQDN resolving into a never-authorise range (e.g. 192.0.2.1) is treated as offline: nothing is whitelisted and its previous IP is removed at once. A provider prefix that overlaps one is refused and revoked, and the row is marked blocked.
Manually-added whitelist entries are never touched.
A provider's published ranges are refetched on their own slower timer and added the same way, tagged fqdn-sync:<provider>.
If a provider list cannot be fetched, its ranges stay authorised and the row is marked stale — a fetch failure never revokes access.
